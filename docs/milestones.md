# 里程碑拆分與驗收標準

**每個里程碑開始前先讀這份，以及對應的細節文件。**

**每完成一個可驗證的階段就停下來讓我確認，不要一次做完整個里程碑。**

---

## M1 — 連線骨架

細節：`docs/01-networking.md`

- Tick 系統（60Hz 固定）
- `InputFrame` 輸入抽象層
- `Dictionary[peer_id]` 玩家管理
- ENet 連線建立、輸入上傳
- 客戶端預測與和解
- 遠端實體插值
- 雙模式啟動（本機主機／專用伺服器）
- 除錯疊層

**不要做戰鬥、敵人、道具、房間切換。**

### 驗收

1. Run Multiple Instances 開兩個視窗，一個 Host 一個 Join `127.0.0.1`，兩個方塊都出現且都能動
2. 本地方塊的移動**感覺不到任何延遲**
3. 遠端方塊的移動平滑，沒有抖動或跳格
4. **人為加入 100ms 模擬延遲後**，本地移動依然零延遲，遠端依然平滑
5. 匯出 dedicated server 版本，用 `--headless` 跑起來不會崩潰，兩個客戶端能同時連上

> 第 4 點是關鍵。本機測試延遲是 0ms，預測和和解的 bug 會完全隱形。

## M2 — 戰鬥基礎（只做劍士一個角色）

細節：`docs/02-characters.md`

- 角色技能系統（含隊友目標的架構，但先只實作劍士）
- 攻擊、投射物系統（架構要通用，弓手與法師之後會用）
- 敵人基礎類別、血量、受傷、死亡
- 敵人攻擊預告系統（明確前搖與危險範圍，長預告時間）
- 走位躲避（**不做幀級無敵閃避**）

**不要在 M2 做弓手或法師。**

### 驗收

兩人（都用劍士）能在一個房間裡打死幾隻敵人，且**在無道具狀態下確實需要躲攻擊才不會死**。

> 這條驗收保證遊戲前期真的有難度。沒有它，很容易做出從頭到尾無腦割草的東西，後期的爽感也會因為缺乏對比而消失。

## M3 — Modifier 架構

細節：`docs/03-items-modifiers.md`

- 事件匯流排
- **觸發係數系統（優先於任何單一道具）**
- Modifier 基底類別與堆疊系統
- 兩種堆疊公式
- 遞迴深度、內部冷卻、每幀觸發上限等防護
- **從道具清單挑 10 個實作**（涵蓋四種稀有度、涵蓋所有事件節點）
- 測試模式

### 驗收

1. **任意組合 10 個道具都不崩潰**，且組合會產生交互
2. 劍士與弓手在同樣的觸發型道具下，**實際觸發頻率不應相差超過 2 倍**

> 第 1 點是刻意寫的。傾向是把道具一個一個做完就交差——請真的去測組合。
> 第 2 點要在測試模式裡拿同一套符文，分別用兩個角色打沙包比較每秒觸發次數。

## M4 — 難度時鐘與房間循環

細節：`docs/04-progression.md`

- 難度值計算與 UI
- 敵人生成器（吃難度值）
- 房間清空 → 傳送門 → 下一房間
- 傳送門充能圓圈
- 寶箱、金錢經濟、掉率分布
- **所有數值集中在單一設定檔**
- 岔路系統（每 5 房間，需兩人都同意才進頭目戰）
- 頭目戰與結算畫面
- 紀錄板（共享，伺服器端）
- 共享解鎖系統（`Set[String]` + 條件判定 + 即時回饋，起始 12 個條件）
- **倒地狀態、輕量救援、真正死亡與下一房間復活**
- 快進模式（跳到第 N 房間 + 自動配發道具）

### 驗收

能連續打 15 個房間，難度明顯上升；**一場完整遊玩（含打王）落在 20 – 30 分鐘**。

---

## M5 — 可讀性與打磨

細節：`docs/05-readability.md`

- 危險色與獨立渲染層
- 特效數量管理
- 敵人描邊
- 死亡回放（受擊環形緩衝區 + 死亡結算畫面）
- 道具部分共享

### 驗收

後期滿螢幕特效時仍看得懂戰況；死亡後能明確知道自己是被什麼打死的。

---

## M6 — 弓手與法師

細節：`docs/02-characters.md`

- 弓手：持續射擊、投射物道具的完整支援
- 法師：法力值資源、蓄力爆發循環、蓄力期間的移動限制
- 法師專屬道具
- 角色選擇介面

**只在 M2 – M5 的劍士手感確定滿意之後才開始。**

### 驗收

**三個角色玩起來的節奏明顯不同。** 特別確認法師不會退化成「用魔法的弓手」——如果兩者操作手感相似，重新設計法師的循環。
