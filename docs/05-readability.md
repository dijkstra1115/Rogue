# 畫面可讀性與死亡回放（M5）

**這是本專案最容易失敗的地方。顏色規則從 M1 就要遵守，不要等到 M5 才處理。**

## 問題

後期玩家特效會蓋滿螢幕，導致看不到敵人的攻擊預告。這對不熟悉這類遊戲的玩家特別致命——她會覺得「我不知道我是怎麼死的」。

## 五條規則

1. **危險色專用**：指定一個顏色（建議品紅或橘紅）**只用於敵人的危險區域**，任何玩家特效都不准使用這個色系
2. **獨立渲染層**：敵人的預告與危險區域畫在專屬的 `CanvasLayer`，**永遠在所有玩家特效之上**
3. **玩家特效自動降透明度**：畫面上特效數量超過閾值時，玩家特效整體降低不透明度
4. **特效數量上限**：超過上限時合併或省略，**寧可少畫也不要糊成一片**
5. **敵人輪廓**：敵人在特效底下時顯示描邊，確保永遠看得到位置

**驗收標準**：後期滿螢幕特效時，玩家仍能清楚看出「哪裡有危險」和「敵人在哪」。

## 死亡回放（配套機制）

因為後期死亡容易變成「突然就沒血了」，必須讓玩家理解發生了什麼。玩家死亡時顯示：

- **致命一擊的來源**（敵人種類、攻擊名稱、傷害數字）
- **死前 3 秒的受擊紀錄**（每次受到的傷害與來源，依時間排序）
- **當時的血量變化曲線**（簡單折線即可）

**實作要求**：每位玩家維持一個受擊環形緩衝區，記錄最近 N 個 tick 的傷害事件（tick、來源、傷害值、剩餘血量）。緩衝區在伺服器端維護，玩家死亡時傳給該客戶端。

**設計意圖**：這是「接受後期混亂」路線的必要配套。**玩家可以接受死得很快，但不能接受不知道原因。**
